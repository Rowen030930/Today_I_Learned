## 오늘 배운 내용

오늘은 C++ 프로그램이 실행 파일로 만들어지는 과정과 기본 문법을 살펴봤다. Visual Studio에서 소스 파일을 열고 빌드하고 실행하는 기본 흐름도 함께 정리했다.

<br>

## 빌드 과정

빌드는 사람이 작성한 소스 코드를 컴퓨터가 실행할 수 있는 프로그램으로 만드는 과정이다.

```text
소스 코드(.cpp)
    ↓ 전처리 및 컴파일
오브젝트 코드(.obj)
    ↓ 링킹
실행 파일(.exe)
```

- **소스 코드**: 사람이 읽고 작성하는 C++ 코드다.
- **컴파일러**: 소스 코드를 컴퓨터가 처리할 수 있는 오브젝트 코드로 변환한다.
- **오브젝트 코드**: 컴파일된 코드지만, 보통 이것만으로는 프로그램을 실행할 수 없다.
- **링커**: 여러 오브젝트 코드와 필요한 라이브러리를 연결해 실행 파일을 만든다.
- **IDE**: 코드 편집, 빌드, 디버깅 등을 한곳에서 할 수 있는 개발 환경이다. Visual Studio가 대표적인 IDE다.

`.cpp` 파일이 여러 개라면 각 파일이 오브젝트 코드로 변환된 뒤, 링커가 이 파일들과 필요한 라이브러리를 묶어 하나의 실행 파일을 만든다.

<br>

## 오류의 종류

오류가 발생한 시점과 원인을 구분하면 문제를 찾기 쉽다.

### 컴파일 오류

문법이 잘못됐거나 필요한 선언을 찾지 못했을 때 발생한다.

아래 예제는 `cout` 문 끝에 세미콜론이 빠져 있어 컴파일 오류가 발생한다.

```cpp
#include <iostream>

int main()
{
    std::cout << "Hello, C++!" // 세미콜론이 빠짐
    return 0;
}
```

### 링커 오류

각 소스 파일의 컴파일은 끝났지만, 필요한 함수나 변수를 연결하지 못했을 때 발생한다.

아래 예제는 `add` 함수를 선언하고 호출했지만, 함수의 실제 정의가 없어 링커 오류가 발생한다.

```cpp
int add(int a, int b); // 함수 선언

int main()
{
    int result = add(3, 4); // 함수 호출
    return 0;
}

// add 함수의 정의가 없음
```

### 실행 시간 오류

프로그램이 빌드된 뒤 실행되는 중에 발생하는 오류다. 아래 예제는 크기가 3인 벡터에서 범위를 벗어난 인덱스에 접근해 실행 중 예외가 발생한다.

```cpp
#include <iostream>
#include <vector>

int main()
{
    std::vector<int> numbers = {10, 20, 30};

    std::cout << numbers.at(3) << std::endl; // 유효한 인덱스는 0~2
    return 0;
}
```

### 논리 오류

프로그램은 실행되지만, 작성한 의도와 다른 결과가 나오는 오류다.

아래 예제는 상품의 총가격을 구하려고 했지만, 곱셈 대신 덧셈을 사용해 잘못된 결과를 출력한다. 예상한 총가격은 `3000`이지만, 실제 출력은 `1003`이다.

```cpp
#include <iostream>

int main()
{
    int price = 1000;
    int quantity = 3;

    int total = price + quantity; // 곱셈을 해야 하지만 덧셈을 사용함

    std::cout << "총가격: " << total << std::endl;
    return 0;
}
```

## C++ 프로그램의 기본 구조

다음은 C++ 프로그램의 기본 구조를 보여주는 예시다.

```cpp
#include <iostream>

int main()
{
    std::cout << "Hello, C++!" << std::endl;
    return 0;
}
```

- `#include <iostream>`: 표준 입출력 기능을 사용하기 위해 관련 헤더를 포함한다.
- `int main()`: 프로그램이 시작되는 함수다.
- `std::cout`: 화면에 내용을 출력한다.
- `std::endl`: 줄을 바꾸고 출력 버퍼를 처리한다.
- `return 0;`: 프로그램이 정상적으로 종료되었음을 나타낸다.

C++ 프로그램은 `main` 함수에서 실행을 시작한다. 따라서 일반적인 실행 프로그램에는 시작점이 되는 `main` 함수가 필요하다.

## 키워드, 지시자, 연산자

### 키워드

키워드는 C++에서 이미 특별한 의미로 정해 둔 단어다. 예를 들어 `int`, `return`, `if`, `while` 등이 있다.

키워드는 변수 이름이나 함수 이름으로 사용할 수 없다.

### 전처리 지시문

전처리 지시문은 컴파일 전에 처리할 내용을 컴파일러에 알려준다. 보통 `#`으로 시작한다.

```cpp
#include <iostream>
```

위 코드는 표준 입출력에 필요한 내용을 현재 프로그램에서 사용할 수 있도록 포함한다.

### 연산자

연산자는 값이나 변수에 연산을 적용하는 기호다.

```cpp
int sum = 3 + 4;
```

- `=`: 오른쪽 값을 왼쪽 변수에 대입한다.
- `+`: 두 값을 더한다.
- `==`: 두 값이 같은지 비교한다.

`=`은 대입 연산자이고, `==`은 비교 연산자이므로 의미가 다르다.

## 주석과 네임스페이스

### 주석

주석은 코드에 설명을 남길 때 사용한다. 컴파일 결과에는 실행 코드로 반영되지 않는다.

```cpp
// 한 줄 주석

/*
여러 줄에 걸친
주석
*/
```

### 네임스페이스

네임스페이스는 이름이 같은 함수나 변수가 충돌하지 않도록 이름을 구분하는 공간이다.

표준 라이브러리의 입출력 기능은 `std` 네임스페이스에 들어 있다.

```cpp
std::cout << "Hello";
```

`std::`를 매번 쓰는 대신 `using namespace std;`를 사용할 수도 있다.

```cpp
#include <iostream>
using namespace std;

int main()
{
    cout << "Hello";
    return 0;
}
```

코드가 커지면 이름 충돌을 피하기 어려울 수 있으므로, `std::cout`처럼 네임스페이스를 명시하는 방식도 알아 두는 것이 좋다.

<br>

## 표준 입출력

C++에서 기본적인 화면 출력에는 `std::cout`, 키보드 입력에는 `std::cin`을 사용한다.

```cpp
#include <iostream>

int main()
{
    int number;

    std::cout << "숫자를 입력하세요: ";
    std::cin >> number;

    std::cout << "입력한 숫자: " << number << std::endl;
    return 0;
}
```

`<<`는 출력할 내용을 `std::cout`으로 전달하고, `>>`는 입력한 값을 변수에 저장한다.

## Visual Studio 기본 사용 흐름과 파일 경로

Visual Studio에서는 솔루션과 프로젝트 안에서 소스 파일을 관리한다.

```text
솔루션
└── 프로젝트
    ├── 소스 파일(.cpp)
    └── 헤더 파일(.h)
```

- **솔루션**: 관련된 프로젝트를 묶어 관리한다.
- **프로젝트**: 프로그램을 빌드하는 데 필요한 설정과 파일을 관리한다.
- **소스 파일**: C++ 코드를 작성하는 `.cpp` 파일이다.
- **헤더 파일**: 선언이나 공통으로 사용할 내용을 담는 `.h` 파일이다.

기본 작업 순서는 다음과 같다.

1. Visual Studio에서 솔루션 또는 프로젝트를 연다.
2. 솔루션 탐색기에서 소스 파일을 선택해 코드를 작성한다.
3. 빌드 메뉴에서 솔루션을 빌드한다.
4. 빌드 오류가 있으면 오류 목록과 출력 창에서 파일 이름과 줄 번호를 확인한다.
5. 빌드가 성공하면 프로그램을 실행해 결과를 확인한다.

파일이 실제로 저장된 위치를 확인할 때는 솔루션 탐색기에서 해당 파일을 찾고, 프로젝트 폴더 안의 파일 경로와 이름을 함께 확인한다. 코드가 여러 파일로 나뉘어 있다면 각 `.cpp` 파일이 프로젝트에 포함되어 있는지도 확인해야 한다.

## 헷갈린 점과 해결 과정

처음에는 컴파일러와 링커가 모두 코드를 실행 파일로 만드는 도구처럼 느껴졌다. 두 단계의 역할을 나눠서 정리했다.

- 컴파일러는 각 소스 코드를 오브젝트 코드로 변환한다.
- 링커는 오브젝트 코드와 필요한 라이브러리를 연결해 실행 파일을 만든다.

따라서 오류 메시지에 컴파일 오류가 보이는지, 링커 오류가 보이는지를 먼저 구분하면 원인을 찾는 데 도움이 된다.

<br>

## 오늘의 정리

C++ 코드는 소스 파일에서 시작해 컴파일 과정을 거쳐 오브젝트 코드가 되고, 링커가 필요한 코드와 라이브러리를 연결하면 실행 파일이 된다. 프로그램은 `main` 함수에서 시작하며, 표준 입출력에는 `std::cout`과 `std::cin`을 사용한다. 오류가 발생하면 컴파일, 링커, 실행 시간, 논리 오류 중 어떤 종류인지 구분하고 메시지와 파일 경로를 확인하며 원인을 찾아야 한다.
