# TIL: Mixamo 8방향 이동 애니메이션 연결하기

## 오늘의 목표

캐릭터가 이동 방향과 속도에 따라 자연스럽게 애니메이션을 바꾸고, 무기를 들었는지에 따라서도 알맞은 동작을 재생하도록 구성한다.

무기를 들지 않았을 때와 들었을 때는 팔과 상체 자세가 다르므로 애니메이션을 따로 준비한다. 각 상태의 이동 애니메이션은 방향과 속도를 기준으로 블렌딩하고, 마지막에 현재 무기 보유 여부로 둘 중 하나를 선택한다.

## 1. Mixamo에서 이동 애니메이션 찾기

![Mixamo에서 스프린트 애니메이션 검색](assets/Mixamo_8Direction_TIL_images/01_mixamo_sprint_search.png)

먼저 Mixamo에서 필요한 이동 애니메이션을 찾았다. 검색 결과를 바로 다운로드하지 않고 미리 재생해, 캐릭터가 원하는 방향으로 이동하는지와 동작이 프로젝트에 어울리는지 확인했다.

이 프로젝트에서는 워크에서 스프린트로 갑자기 넘어가는 느낌을 줄이려고 런을 중간 단계로 추가했다.

- 워크: 이동을 시작하거나 천천히 움직일 때
- 런: 워크에서 스프린트로 넘어가는 중간 속도
- 스프린트: Shift를 누르고 빠르게 이동할 때

런 애니메이션이 있으면 워크와 스프린트 사이의 속도 차이를 나눠 표현할 수 있다. 설정한 기준 속도는 워크 `300`, 런 `375`, 스프린트 `500`이다.

<br>

### 다운로드 옵션

- `In Place`: 켬
- `Skin`: 없음

`In Place`를 켠 이유는 애니메이션이 캐릭터를 실제로 앞으로 밀지 않도록 하기 위해서다. 캐릭터의 위치와 이동 거리는 언리얼 엔진의 이동 시스템이 처리하고, 애니메이션은 걷기나 달리기 동작만 보여준다. 이렇게 해야 게임 이동 속도와 애니메이션 재생을 따로 조절하기 쉽다.

`Skin`을 제외하면 캐릭터 메시를 애니메이션 파일마다 반복해서 가져오지 않아도 된다. 애니메이션 데이터만 사용하므로 임포트 파일을 정리하기도 편하다.

## 2. FBX 임포트 시 기존 Mixamo 스켈레톤 사용

![FBX 임포트 창에서 기존 Mixamo 스켈레톤 선택](assets/Mixamo_8Direction_TIL_images/02_fbx_import_skeleton.png)

애니메이션을 가져올 때 기존 캐릭터가 사용하는 Mixamo 스켈레톤을 선택했다.

애니메이션은 특정 스켈레톤의 뼈 구조를 기준으로 만들어진다. 같은 스켈레톤을 선택하면 애니메이션이 캐릭터의 뼈에 맞게 연결된다. 반대로 다른 스켈레톤으로 가져오면 뼈 이름이나 구조가 달라 애니메이션이 맞지 않을 수 있다. 그런 경우에는 리타게팅 작업이 필요하다.

이번 작업에서는 리타게팅 과정을 새로 만들지 않도록, Mixamo에서 사용하던 스켈레톤을 그대로 선택했다.

## 3. 무기 미장착 이동 블렌드 스페이스 만들기

![무기 미장착 이동 블렌드 스페이스](assets/Mixamo_8Direction_TIL_images/03_unarmed_blendspace.png)

무기를 들지 않았을 때 사용할 애니메이션을 `BS_Unarmed_Locomotion` 블렌드 스페이스에 모았다.

블렌드 스페이스를 사용하면 방향과 속도에 따라 애니메이션을 선택하고, 샘플 사이에서는 동작을 섞을 수 있다. 방향마다 애니메이션 상태를 전부 따로 전환하는 것보다 이동 방향이 바뀔 때 부드럽게 대응하기 쉽다.

이 블렌드 스페이스의 축은 다음과 같다.

- `Direction`: 캐릭터가 바라보는 방향을 기준으로 이동하는 방향
- `Speed`: 캐릭터가 실제로 이동하는 속도

8방향의 Direction 값은 다음처럼 사용했다.

| 이동 방향 | Direction |
|---|---:|
| 앞 | `0°` |
| 앞-오른쪽 | `45°` |
| 오른쪽 | `90°` |
| 뒤-오른쪽 | `135°` |
| 뒤 | `180°` 또는 `-180°` |
| 뒤-왼쪽 | `-135°` |
| 왼쪽 | `-90°` |
| 앞-왼쪽 | `-45°` |

앞, 옆, 뒤, 대각선 방향 샘플을 배치한 이유는 캐릭터가 바라보는 방향을 유지한 채 옆이나 뒤로 이동할 때도 그 방향에 맞는 동작을 재생하기 위해서다.

Speed 축에는 워크 `300`, 런 `375`, 스프린트 `500`을 기준으로 샘플을 배치했다. 값이 이 사이에 들어오면 블렌드 스페이스가 인접한 샘플을 섞어 중간 속도 동작을 표현한다.

뒤로 이동할 때는 스프린트 샘플을 두지 않았다. 뒤로 달리는 애니메이션이 준비되어 있지 않으면, 속도만 높였을 때 걷기 동작이 빠르게 재생되어 어색해질 수 있기 때문이다.

## 4. 무기 장착 이동 블렌드 스페이스 만들기

![무기 장착 이동 블렌드 스페이스](assets/Mixamo_8Direction_TIL_images/04_rifle_blendspace.png)

무기를 들었을 때 사용할 이동 애니메이션은 `BS_Rifle_Directional` 블렌드 스페이스에 따로 배치했다.

무기를 들면 팔이 총을 잡고 상체가 조준 자세를 유지한다. 맨손 이동 애니메이션을 그대로 사용하면 손이 무기에서 떨어지거나 팔과 총의 자세가 어긋날 수 있다. 그래서 무기 장착 애니메이션과 맨손 애니메이션을 별도의 블렌드 스페이스로 분리했다.

무기 장착 상태에서도 워크 `300`, 런 `375`, 스프린트 `500`을 기준으로 이동 속도에 맞는 동작을 배치한다. 다만 뒤로 달리는 애니메이션이 없으므로 뒤쪽 방향에는 스프린트 동작을 사용하지 않는다.

**속도값 확인:** 스크린샷에서 무기 장착 상태의 뒤로 걷기 샘플은 `275`로 표시되어 있다. 워크 속도를 `300`으로 통일하려는 설정이라면 이 샘플도 `300`으로 맞추는 게 좋다. `275`를 유지하려면 뒤로 이동할 때만 다른 속도 기준을 쓰는 이유를 기록해 두면 이후 조정할 때 헷갈리지 않는다.

## 5. 애님 블루프린트에서 방향과 속도 계산하기

![Direction과 Speed를 계산하는 이벤트 그래프](assets/Mixamo_8Direction_TIL_images/05_direction_speed_event_graph.png)

블렌드 스페이스가 사용할 `Direction`과 `Speed`를 매 프레임 갱신하도록 `Event Blueprint Update Animation`에서 계산했다.

### Direction 계산

`Try Get Pawn Owner`로 이 애님 블루프린트를 사용하는 캐릭터를 찾는다. `Get Velocity`로 이동 속도를 가져오고, `Get Actor Rotation`으로 캐릭터가 바라보는 방향을 가져온 뒤 `Calculate Direction`에 전달한다.

`Calculate Direction`을 사용하는 이유는 월드 기준의 이동 방향이 아니라 **캐릭터가 바라보는 방향을 기준으로** 앞, 뒤, 옆 이동을 구하기 위해서다. 예를 들어 캐릭터가 앞을 바라본 채 왼쪽으로 이동하면 왼쪽 방향 애니메이션을 선택할 수 있다.

### Speed 계산

`Get Velocity`의 결과를 `Vector Length XY`에 연결해 수평 속도의 크기를 계산하고 `Speed` 변수에 저장한다.

수평 속도만 계산하는 이유는 점프나 낙하 중의 높이 변화가 이동 속도에 섞이지 않도록 하기 위해서다. 이렇게 계산한 값은 블렌드 스페이스의 Speed 축에 전달된다.

Shift를 누르면 캐릭터 이동 설정에서 속도가 스프린트 속도까지 올라가야 한다. 애님 블루프린트는 입력 키 자체가 아니라 실제 속도를 읽으므로, 캐릭터의 이동 속도가 바뀌지 않으면 스프린트 애니메이션도 선택되지 않는다.

## 6. 무기 미장착 블렌드 스페이스를 애님 그래프에 연결하기

![무기 미장착 블렌드 스페이스를 Output Pose에 연결](assets/Mixamo_8Direction_TIL_images/06_unarmed_animgraph.png)

먼저 `BS_Unarmed_Locomotion`을 애님 그래프에 연결했다.

- `Direction` 변수 → 블렌드 스페이스의 `Direction`
- `Speed` 변수 → 블렌드 스페이스의 `Speed`
- 블렌드 스페이스 출력 → `Output Pose`

이 연결은 맨손 이동 애니메이션이 올바르게 출력되는 기본 경로가 된다. 방향과 속도 계산이 맞는지 먼저 확인해 두면, 이후 무기 상태를 추가했을 때 문제가 애님 그래프의 선택 로직인지 블렌드 스페이스 자체인지 구분하기 쉽다.

## 7. 캐릭터가 무기를 들었는지 확인하기

![Current Weapon의 유효성을 확인하는 이벤트 그래프](assets/Mixamo_8Direction_TIL_images/07_check_current_weapon.png)

애님 그래프가 맨손과 무기 장착 상태를 구분할 수 있도록 `Has Weapon` 변수를 갱신했다.

1. `Try Get Pawn Owner`로 애님 블루프린트를 사용하는 캐릭터를 가져온다.
2. `Cast To BP_ThirdPersonCharacter`로 캐릭터 블루프린트에 접근한다.
3. `Current Weapon` 변수를 가져온다.
4. `Is Valid`로 현재 무기 객체가 존재하는지 확인한다.
5. 무기가 유효하면 `Has Weapon`을 `true`로 설정한다.
6. 무기가 없으면 `Has Weapon`을 `false`로 설정한다.

`Current Weapon`은 캐릭터가 현재 장착한 무기 객체를 가리킨다. `Is Valid`로 확인하는 이유는 무기 객체가 없는 상태에서 그 객체를 사용하려는 문제를 피하면서, 장착 여부를 간단한 참·거짓 값으로 전달하기 위해서다.

## 8. 무기 여부에 따라 포즈 선택하기

![Has Weapon으로 무기와 맨손 포즈를 선택하는 애님 그래프](assets/Mixamo_8Direction_TIL_images/08_blend_poses_by_bool.png)

`Blend Poses by Bool` 노드에 두 블렌드 스페이스를 연결하고 `Has Weapon` 값으로 출력할 포즈를 선택했다.

- `BS_Rifle_Directional` 출력 → `True Pose`
- `BS_Unarmed_Locomotion` 출력 → `False Pose`
- `Has Weapon` → `Active Value`
- `Blend Poses by Bool` 출력 → `Output Pose`

`Has Weapon`이 참이면 무기 장착 포즈를, 거짓이면 맨손 포즈를 선택한다. 이 노드를 사용하면 무기를 장착할 때마다 애님 그래프 전체를 다른 애니메이션 블루프린트로 바꾸지 않고 하나의 그래프 안에서 상태를 전환할 수 있다.

`True Blend Time`과 `False Blend Time`을 설정한 이유는 포즈가 바뀌는 순간 동작이 갑자기 튀지 않도록 전환 시간을 주기 위해서다.

## 헷갈렸던 점과 해결 과정

- `Direction`은 월드에서 캐릭터가 향하는 절대 각도가 아니다. 캐릭터가 바라보는 방향을 기준으로 이동 방향을 나타낸다.
- `Speed`를 입력 키로 결정하지 않고 실제 속도로 계산했다. 그래야 걷기와 런 사이의 속도처럼 중간값에도 맞춰 애니메이션을 섞을 수 있다.
- `In Place`를 사용한 이유는 애니메이션 자체가 캐릭터를 이동시키지 않도록 하여, 실제 이동 거리와 속도를 언리얼 엔진에서 관리하기 위해서다.
- 맨손과 무기 장착 애니메이션을 나눈 이유는 총을 들었을 때 손과 상체 자세가 무기에 맞게 유지되어야 하기 때문이다.
- 뒤로 달리는 샘플이 없으므로 뒤로 이동할 때 스프린트하지 않도록 했다. 없는 동작을 빠른 속도로 재생하면 애니메이션이 부자연스러워질 수 있다.
- 무기 장착 블렌드 스페이스의 뒤로 걷기 샘플이 `275`로 설정되어 있어, 워크 기준인 `300`과 통일할지 확인이 필요하다.
- 애니메이션을 가져올 때 기존 Mixamo 스켈레톤을 선택했다. 스켈레톤이 다르면 그대로 적용되지 않을 수 있어 리타게팅이 필요하다.

## 오늘 배운 내용 정리

Mixamo에서 `In Place`와 `Skin 없음` 옵션으로 이동 애니메이션을 준비하고, 언리얼 엔진에 가져올 때 기존 Mixamo 스켈레톤을 지정했다. 워크 `300`, 런 `375`, 스프린트 `500`으로 속도 단계를 나눈 이유는 이동 속도 변화에 맞는 동작을 제공하기 위해서다. 뒤로 달리는 애니메이션이 없어 뒤쪽 방향의 스프린트는 사용하지 않았다.

맨손과 무기 장착 애니메이션을 별도의 블렌드 스페이스로 관리했다. 애님 블루프린트에서 캐릭터가 바라보는 방향과 실제 수평 속도를 계산하고, `Current Weapon`이 유효한지 확인해 `Has Weapon` 값을 만든다. 마지막으로 이 값으로 포즈를 선택하고, 플레이 영상을 통해 실제 연결 결과를 확인했다.
