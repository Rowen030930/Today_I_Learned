# TIL: 공간 복잡도와 메모리 사용량

<br>

## 오늘 배운 내용

공간 복잡도(Space Complexity)는 입력 크기가 커질 때 프로그램이 사용하는 메모리가 얼마나 늘어나는지를 나타낸다.

배열, `vector` 같은 컨테이너뿐 아니라 재귀 함수 호출 중 쌓이는 메모리도 고려한다. 실제 메모리 제한을 확인할 때는 전역·정적 변수, 동적 할당, 지역 변수와 재귀 호출 등 프로그램이 사용하는 공간을 함께 살펴봐야 한다.

## 배열 크기로 메모리 계산하기

`int` 배열이 N개 원소를 저장한다면 필요한 메모리는 대략 다음과 같다.

```text
N × sizeof(int) bytes
```

많은 환경에서 `sizeof(int)`는 4바이트지만, 실제 크기는 `sizeof(int)`로 확인해야 한다.

```cpp
#include <iostream>

int main()
{
    std::cout << sizeof(int) << " bytes\n";
}
```

예를 들어 `int` 원소 10,000,000개를 저장하면 `int`가 4바이트인 환경에서 약 40,000,000바이트, 즉 약 38.1 MiB가 필요하다. 입력 크기 N에 비례하는 배열이라면 공간 복잡도는 `O(N)`이다. 빅오 표기에서는 상수 계수를 생략하기 때문이다.

```cpp
int values[10000000]; // 실제 메모리는 크지만, 크기가 고정되어 있음
```

이 배열의 실제 크기는 약 40MB지만, 배열 크기가 입력과 무관하게 고정되어 있다면 입력 크기 기준 공간 복잡도는 `O(1)`이다. 반대로 입력 N에 따라 원소 N개를 저장한다면 `O(N)`이다.

```cpp
std::vector<int> values(n); // n이 입력 크기에 따라 달라지면 O(N)
```

> 공간 복잡도는 입력에 따라 메모리 사용량이 어떻게 변하는지를 보는 개념이다. 따라서 고정 크기 배열의 메모리가 크다는 사실과, 그 배열이 `O(1)`인지 `O(N)`인지는 구분해야 한다.

## 메모리는 어디에 사용될까?

- **전역·정적 영역**: 전역 변수와 `static` 변수 등이 차지한다.
- **힙(Heap)**: `new`, `std::vector` 등 동적으로 확보한 저장 공간이 사용한다. `vector`는 현재 원소 수뿐 아니라 확보한 용량도 메모리에 영향을 준다.
- **스택(Stack)**: 함수의 지역 변수와 함수 호출 정보가 저장된다. 재귀가 깊어지면 호출 스택도 커진다.

재귀 호출이 최대 깊이 D까지 이어지고 호출마다 필요한 스택 공간이 대략 일정하다면, 재귀 호출 스택은 보통 `O(D)`로 볼 수 있다. 실제 호출 한 번의 크기는 컴파일러와 코드에 따라 달라지므로, 깊은 재귀가 메모리 제한이나 스택 한도를 넘지 않는지 확인해야 한다.

## 2차원 배열과 메모리 제한

2차원 `int` 배열이 N행 M열이라면 원소 수는 `N × M`이고, 필요한 메모리는 대략 다음과 같다.

```text
N × M × sizeof(int) bytes
```

예를 들어 `int`가 4바이트인 환경에서 `10000 × 10000` 배열은 다음만큼의 공간을 사용한다.

```text
10000 × 10000 × 4
= 400,000,000 bytes
≈ 381.5 MiB
```

따라서 512 MiB 제한에서는 배열 자체가 제한보다 작다. 다만 프로그램의 다른 메모리 사용량과 실행 환경의 오버헤드도 함께 계산해야 한다. 메모리 제한을 통과할지는 배열 하나의 크기만으로 단정할 수 없다.

---

<br>

## 메모리 제한을 확인하는 순서

1. **입력의 최대 범위를 확인한다.**  
   배열이나 컨테이너가 최대 몇 개의 데이터를 저장해야 하는지 확인한다.

2. **필요한 배열의 크기를 계산한다.**  
   예를 들어 2차원 배열은 `행 수 × 열 수 × 원소 크기`로 계산한다.

3. **다른 메모리도 더해 본다.**  
   `visited` 배열, `vector`의 용량, 재귀 호출 스택, 기타 자료구조가 추가로 공간을 사용한다.

4. **메모리 제한과 비교한다.**  
   배열 크기만 제한에 딱 맞추기보다 실행에 필요한 추가 메모리를 고려해 여유를 둔다.

## 메모리 계산에서 주의할 점

`512MB`라는 표기는 실행 환경에 따라 512,000,000바이트를 뜻할 수도 있고, 512 MiB(536,870,912바이트)를 뜻할 수도 있다. 또한 온라인 저지마다 메모리 측정 방식이 다를 수 있다.

수업에서 제시된 `int` 배열 원소 수 기준은 빠르게 가늠하기 위한 보수적인 경험칙으로 활용할 수 있다.

| 메모리 제한 | 수업 자료의 대략적인 `int` 배열 원소 수 |
| --- | ---: |
| 64MB | 약 1,500만 개 |
| 128MB | 약 3,000만 개 |
| 256MB | 약 6,000만 개 |
| 512MB | 약 1억 2,000만 개 |

이 수치는 실제로 사용할 수 있는 원소 수를 보장하지 않는다. `sizeof(int)`, 메모리 제한의 단위, 다른 자료구조의 사용량, 실행 환경에 따라 달라지므로 최종 판단은 문제의 메모리 제한과 코드의 전체 메모리 사용량을 기준으로 해야 한다.

## C++ 배열 크기에 관한 주의

아래처럼 입력값을 바로 고정 배열 크기로 사용하는 코드는 표준 C++에서 허용되지 않는다.

```cpp
int n;
std::cin >> n;

int values[n]; // 표준 C++ 배열은 크기가 컴파일 시점에 정해져야 함
```

입력에 따라 크기가 달라지는 배열이 필요하다면 보통 `std::vector`를 사용한다.

```cpp
int n;
std::cin >> n;

std::vector<int> values(n);
```

## 헷갈렸던 점과 정리

- **배열이 크면 언제나 `O(N)`인가?**  
  아니다. 입력 크기와 관계없이 고정된 크기라면 입력 크기 기준으로는 `O(1)`이다. 입력에 따라 크기가 늘어나면 `O(N)`처럼 표현한다.

- **전역 배열은 공간 복잡도에서 빼도 되는가?**  
  빼면 안 된다. 실제 메모리 제한을 확인할 때는 전역·정적 배열도 프로그램이 사용하는 메모리에 포함된다. 복잡도 분석에서는 입력 데이터 공간을 포함했는지, 보조 공간만 계산했는지를 함께 밝혀야 한다.

- **재귀 함수는 왜 메모리를 사용하는가?**  
  함수가 다시 호출될 때마다 호출 정보와 지역 변수 등이 쌓인다. 재귀 깊이가 커지면 스택 메모리도 커질 수 있다.

- **`int`는 무조건 4바이트인가?**  
  항상 그렇다고 가정하지 않는다. 실제 환경에서는 `sizeof(int)`로 확인한다.

## 오늘 배운 내용 요약

공간 복잡도는 입력 크기가 달라질 때 프로그램의 메모리 사용량이 어떻게 변하는지를 나타낸다. 배열과 컨테이너의 원소 수뿐 아니라 재귀 호출 스택도 고려해야 한다. 문제를 풀 때는 입력의 최대 범위와 메모리 제한을 확인하고, 필요한 자료구조와 그 밖의 메모리 사용량을 함께 계산해야 한다.
