# TIL: 문제로 연습하는 시간 복잡도

<br>

## 오늘 배운 내용

시간 복잡도는 입력 크기가 커질 때 프로그램의 작업량이 얼마나 증가하는지 나타낸다. 실행 시간을 초 단위로 재는 대신, 반복문이나 함수 호출 횟수가 입력 크기에 따라 어떻게 늘어나는지 살펴본다.

코드의 실행 결과가 무엇인지는 시간 복잡도와 별개의 문제다. 예를 들어 계산 결과가 항상 `0`이더라도 반복이나 함수 호출이 많다면 시간 복잡도는 커질 수 있다.

---

<br>

## Q1. 중첩 반복문

```cpp
for (int i = 0; i < n; i++) {
    for (int j = 0; j < i; j++) {
        a += i + j;
    }
}
```

바깥 반복문은 `i`가 `0`부터 `n - 1`까지 변한다. 안쪽 반복문은 매번 `i`번 실행된다.

전체 실행 횟수는 다음과 같다.

```text
0 + 1 + 2 + ... + (n - 1)
= n(n - 1) / 2
```

가장 큰 항은 `n²`에 비례하므로 시간 복잡도는 **O(n²)**이다.

안쪽 반복문이 매번 `n`번 실행되는 것은 아니지만, 횟수를 모두 더하면 제곱에 비례하는 작업량이 된다.

## Q2. 차례로 실행되는 반복문

```cpp
for (int i = 0; i < N; i++) {
    a *= i;
}

for (int j = 0; j < M; j++) {
    a *= j;
}
```

첫 번째 반복문은 `N`번, 두 번째 반복문은 `M`번 실행된다. 두 반복문은 중첩된 것이 아니라 차례로 실행되므로 작업량을 더한다.

```text
N + M
```

따라서 시간 복잡도는 **O(N + M)**이다.

첫 번째 반복문에서 `i`가 `0`일 때 `a`가 `0`이 되지만, 이 계산 결과는 반복 횟수에 영향을 주지 않는다. 시간 복잡도는 값의 결과가 아니라 작업이 얼마나 반복되는지를 기준으로 판단한다.

## Q3. 배열을 반으로 나누는 재귀 함수

```cpp
int go(int l, int r) {
    if (l == r) return a[l];

    int mid = (l + r) / 2;
    int sum = go(l, mid) + go(mid + 1, r);
    return sum;
}
```

각 함수 호출은 범위를 절반으로 나누고, 양쪽 범위에 대해 재귀 호출을 한다. 원소 하나만 남을 때까지 나누므로 잎에 해당하는 호출이 배열의 원소 수만큼 생긴다.

각 호출에서 수행하는 나누기, 덧셈, 반환 처리는 상수 시간이다. 전체 원소를 한 번씩 처리하므로 시간 복잡도는 **O(n)**이다.

```text
T(n) = 2T(n / 2) + O(1)
```

재귀 호출이 두 갈래로 나뉜다고 해서 무조건 `O(2^n)`이 되는 것은 아니다. 여기서는 입력 범위를 계속 절반으로 줄이며 전체 원소를 처리하므로 `O(n)`이다.

## Q4. 값을 절반으로 줄이는 반복문

```cpp
int i = N;

while (i > 0) {
    a += i;
    i /= 2;
}
```

반복할 때마다 `i`가 절반으로 줄어든다.

```text
N → N / 2 → N / 4 → N / 8 → ...
```

`N`을 절반으로 몇 번 나누어야 1 이하가 되는지를 나타내는 횟수는 약 `log₂N`이다. 따라서 시간 복잡도는 **O(log N)**이다.

로그는 어떤 수를 만들기 위해 밑을 몇 번 곱해야 하는지를 나타낸다. 예를 들어 `2`를 네 번 곱하면 `16`이므로 `log₂16 = 4`다.

## Q5. 한 번 호출할 때마다 세 번 재귀 호출하는 함수

```cpp
void solve(int N) {
    cnt++;
    cout << cnt << '\n';

    if (N == 0) return;

    for (int i = 0; i < 3; i++) {
        solve(N - 1);
    }
}
```

`N`이 0이 아니면 함수가 자기 자신을 세 번 호출한다. 각 재귀 단계마다 호출 수가 세 배로 늘어난다.

```text
깊이 0: 1번
깊이 1: 3번
깊이 2: 9번
깊이 3: 27번
...
깊이 N: 3^N번
```

함수 전체 호출 수는 등비수열의 합으로 나타낼 수 있다.

```text
1 + 3 + 3² + ... + 3^N
= (3^(N + 1) - 1) / (3 - 1)
```

가장 깊은 단계의 호출 수가 `3^N`에 비례하므로 시간 복잡도는 **O(3^N)**이다.

제공된 그림의 유한 등비수열 합 공식은 다음과 같다.

```text
a + ar + ar² + ... + ar^(n - 1)
= a(r^n - 1) / (r - 1)
```

여기서 `a`는 첫 항, `r`은 공비다. 재귀 호출 수를 셀 때는 첫 호출부터 마지막 깊이까지의 항을 더하는 데 사용할 수 있다.

그림의 무한 등비급수 공식은 다음과 같다.

```text
a + ar + ar² + ...
= a / (1 - r)   (|r| < 1)
```

이 공식은 공비의 절댓값이 1보다 작을 때만 수렴한다. `Q5`의 공비는 `3`이므로 무한급수 공식이 아니라 유한 등비수열 합을 적용한다.

## 헷갈린 점과 해결 과정

- 반복문이 두 개라는 이유만으로 시간 복잡도가 항상 곱해지는 것은 아니다. 중첩되어 있으면 반복 횟수를 곱하고, 차례로 실행되면 더한다.
- 재귀 호출이 여러 갈래로 나뉘어도 입력 크기가 어떻게 줄어드는지 함께 봐야 한다. `Q3`은 범위를 절반씩 나누며 원소를 처리해 `O(n)`이고, `Q5`는 매 단계 세 갈래 호출을 만들어 `O(3^n)`이다.
- 계산 결과가 `0`이 되는 것과 시간 복잡도는 서로 다른 문제다. `Q2`에서 `a`의 값이 `0`이 되더라도 반복문은 계속 실행된다.

## 오늘 배운 내용 정리

- 중첩 반복문의 횟수는 각 반복 횟수를 합산해 판단한다. `Q1`은 `O(n²)`이다.
- 차례로 실행하는 반복문은 각 작업량을 더한다. `Q2`는 `O(N + M)`이다.
- 반씩 나누며 모든 원소를 처리하는 재귀 함수는 `O(n)`이 될 수 있다. `Q3`이 이에 해당한다.
- 반복할 때마다 입력을 절반으로 줄이면 `O(log N)`이다. `Q4`가 이에 해당한다.
- 재귀 호출이 매 단계 세 배로 늘어나면 호출 수가 등비수열처럼 증가한다. `Q5`는 `O(3^N)`이다.
