# TIL: 입력 크기에 따라 달라지는 시간 복잡도

## 오늘 배운 내용

시간 복잡도는 **입력 크기가 커질 때 프로그램이 처리해야 하는 작업량이 어떻게 변하는지** 살펴보는 기준이다.

실제 실행 시간은 컴퓨터 성능이나 프로그램 실행 환경에 따라 달라질 수 있다. 그래서 시간을 초 단위로 재기보다, 입력 크기에 따라 반복되는 작업 횟수가 어떻게 늘어나는지 확인한다.

<br>

## 반복문에서 작업 횟수 세기

이미지에는 세 개의 중첩 반복문과 그 뒤에 이어지는 반복문이 있다.

```cpp
for (int i = 0; i < 10; i++)
{
    for (int j = 0; j < n; j++)
    {
        for (int k = 0; k < n; k++)
        {
            // 단순한 작업
        }
    }
}

for (int i = 0; i < n; i++)
{
    // 단순한 작업
}
```

첫 번째 묶음의 반복 횟수를 세어 보면 다음과 같다.

- 가장 바깥 반복문은 항상 10번 실행된다.
- 가운데 반복문은 바깥 반복문이 한 번 실행될 때마다 `n`번 실행된다.
- 가장 안쪽 반복문은 가운데 반복문이 한 번 실행될 때마다 `n`번 실행된다.

따라서 첫 번째 묶음의 작업 횟수는 다음과 같다.

```text
10 × n × n = 10n²
```

그 뒤에 있는 반복문은 `n`번 실행되므로, 두 번째 묶음의 작업 횟수는 다음과 같다.

```text
n
```

두 묶음이 차례대로 실행되므로 전체 작업 횟수는 다음과 같다.

```text
10n² + n
```

<br>

## 코드로 작업 횟수 확인하기

아래 코드는 각 반복문 안의 작업이 몇 번 실행되는지 센다.

```cpp
#include <iostream>

int main()
{
    int n;
    std::cin >> n;

    long long nestedWork = 0;
    long long singleWork = 0;

    // 이미지의 첫 번째 묶음
    for (int i = 0; i < 10; i++)
    {
        for (int j = 0; j < n; j++)
        {
            for (int k = 0; k < n; k++)
            {
                ++nestedWork;
            }
        }
    }

    // 이미지의 두 번째 묶음
    for (int i = 0; i < n; i++)
    {
        ++singleWork;
    }

    std::cout << "중첩 반복문 작업 횟수: " << nestedWork << '\n';
    std::cout << "단일 반복문 작업 횟수: " << singleWork << '\n';
    std::cout << "전체 작업 횟수: " << nestedWork + singleWork << '\n';
}
```

입력:

```text
3
```

예상 출력:

```text
중첩 반복문 작업 횟수: 90
단일 반복문 작업 횟수: 3
전체 작업 횟수: 93
```

`n`이 3이면 첫 번째 묶음은 `10 × 3 × 3`, 즉 90번 실행된다. 두 번째 묶음은 3번 실행된다. 따라서 전체 작업 횟수는 `90 + 3 = 93`이다.

<br>

## 반복문이 차례대로 있을 때와 겹쳐 있을 때

반복문 두 개가 차례대로 있으면 각각의 작업 횟수를 더한다.

```cpp
for (int i = 0; i < n; i++)
{
    // n번 실행
}

for (int j = 0; j < n; j++)
{
    // n번 실행
}
```

각 반복문의 작업 횟수를 더하면 다음과 같다.

```text
n + n = 2n
```

반복문이 중첩되어 있으면 바깥 반복 횟수와 안쪽 반복 횟수를 곱한다.

```cpp
for (int i = 0; i < n; i++)
{
    for (int j = 0; j < n; j++)
    {
        // n × n번 실행
    }
}
```

작업 횟수는 다음과 같다.

```text
n × n = n²
```
<br>

## 작업 횟수가 늘어나는 모습

이미지의 반복문에서 전체 작업 횟수는 `10n² + n`이다.

| `n` | 중첩 반복문 작업 횟수 `10n²` | 단일 반복문 작업 횟수 `n` | 전체 작업 횟수 |
|---:|---:|---:|---:|
| 1 | 10 | 1 | 11 |
| 2 | 40 | 2 | 42 |
| 3 | 90 | 3 | 93 |
| 10 | 1,000 | 10 | 1,010 |

`n`이 커질수록 중첩 반복문에서 실행되는 작업이 빠르게 늘어나는 것을 확인할 수 있다. 시간 복잡도를 살펴볼 때는 이런 식으로 입력 크기와 반복되는 작업 횟수의 관계를 확인한다.

<br>

## 헷갈린 점과 해결 과정

### 시간 복잡도는 실제 실행 시간을 뜻하나요?

실행 시간을 살펴보는 데 도움이 되는 기준이지만, 시간 복잡도 자체가 초 단위의 실행 시간은 아니다. 실제 실행 시간은 컴퓨터 성능과 실행 환경에 따라서도 달라진다.

### 반복문이 두 개면 무조건 곱하나요?

반복문이 서로 중첩되어 있으면 반복 횟수를 곱한다. 반복문이 차례대로 따로 실행되면 각 작업 횟수를 더한다.

### `cout`으로 출력하는 시간도 같은 방식으로 세면 되나요?

이 예제에서는 반복문 안의 작업 하나를 같은 비용의 단순 작업으로 보고 횟수를 센다. 실제 출력 작업은 출력하는 데이터의 양이나 실행 환경에 따라 더 많은 시간이 걸릴 수 있다.

<br>

## 오늘의 배운 내용 정리

- 시간 복잡도는 입력 크기에 따라 작업량이 어떻게 변하는지 살펴보는 기준이다.
- 실제 실행 시간과 작업 횟수는 같은 뜻이 아니다.
- 중첩된 반복문은 각 반복 횟수를 곱해 작업량을 계산한다.
- 차례대로 실행되는 반복문은 각 작업 횟수를 더한다.
- 이미지의 코드에서 작업 횟수는 `10n² + n`이다.
- 입력 크기가 커질 때 반복 작업이 얼마나 늘어나는지 살펴보는 것이 중요하다.
