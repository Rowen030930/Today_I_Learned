# TIL: 배열에서 포인터로의 변환 (Array-to-Pointer Decay)

## 오늘 배운 내용

C++의 내장 배열은 대부분의 식에서 배열 이름을 사용하면 **첫 번째 원소를 가리키는 포인터로 변환**된다. 이 변환을 **array-to-pointer decay**라고 한다.

```cpp
int arr[3] = {1, 2, 3};
int* ptr = arr;
```

여기서 `arr`은 대부분의 식에서 `&arr[0]`과 같은 시작 주소로 변환된다.

```cpp
int* ptr = arr;       // 첫 번째 원소를 가리킴
int* ptr2 = &arr[0];  // 위와 같은 주소
```

## 코드 예시

```cpp
#include <iostream>

int main()
{
    int arr[3] = {1, 2, 3};
    int* ptr = arr;

    std::cout << "첫 번째 원소: " << arr[0] << '\n';
    std::cout << "포인터가 가리키는 값: " << *ptr << '\n';
    std::cout << "두 번째 원소: " << *(ptr + 1) << '\n';
    std::cout << std::boolalpha;
    std::cout << "ptr과 &arr[0]의 주소가 같은가: "
              << (ptr == &arr[0]) << '\n';
    std::cout << "배열 원소 개수: "
              << sizeof(arr) / sizeof(arr[0]) << '\n';

    return 0;
}
```

<br>

### 예상 출력

```text
첫 번째 원소: 1
포인터가 가리키는 값: 1
두 번째 원소: 2
ptr과 &arr[0]의 주소가 같은가: true
배열 원소 개수: 3
```

`ptr + 1`은 다음 정수 원소의 위치를 가리킨다. 포인터 연산은 바이트 단위로 1을 더하는 것이 아니라, 포인터가 가리키는 타입의 크기만큼 다음 원소로 이동한다.

<br>

## 배열과 포인터의 차이

배열 이름이 포인터처럼 사용되더라도 **배열 자체가 포인터인 것은 아니다**.

배열에는 원소 개수와 전체 크기 정보가 있지만, 배열 이름이 포인터로 변환된 뒤에는 그 포인터만으로 배열의 원소 개수를 알 수 없다. 배열 크기가 필요하다면 배열인 상태에서 확인해야 한다.

```cpp
int arr[3] = {1, 2, 3};
int* ptr = arr;

std::cout << sizeof(arr); // 배열 전체 크기
std::cout << sizeof(ptr); // 포인터 변수 자체의 크기
```

`sizeof(arr)`와 `sizeof(ptr)`는 서로 다른 정보를 확인한다. 포인터의 크기는 실행 환경에 따라 달라질 수 있다.

배열 이름이 모든 상황에서 포인터로 변환되는 것은 아니다. 예를 들어 `sizeof(arr)`에서는 배열 전체의 크기를 확인하며, `&arr`은 첫 번째 원소의 주소가 아니라 배열 전체를 가리키는 포인터를 만든다.

<br>

## 배열은 어디에 저장되는가?

배열이 저장되는 위치와 array-to-pointer decay는 서로 다른 개념이다. 배열 이름의 변환 규칙은 배열이 스택, 정적 저장 영역, 힙 중 어디에 저장되는지에 따라 달라지지 않는다.

| 배열 예시 | 저장 방식 |
|---|---|
| 함수 안에서 선언한 지역 배열 | 자동 저장 기간을 가짐. 보통 스택을 사용하는 방식으로 구현됨 |
| 전역 배열이나 `static` 배열 | 정적 저장 기간을 가짐 |
| `new[]`로 만든 배열 | 동적 저장 기간을 가짐. `new[]`의 결과로 포인터를 받음 |

예를 들어 지역 배열도 포인터에 대입하면 첫 번째 원소를 가리키는 포인터로 변환된다.

```cpp
void example()
{
    int localArray[3] = {1, 2, 3};
    int* ptr = localArray; // 지역 배열도 decay 가능
}
```

동적 배열은 `new[]`의 결과가 포인터이므로 포인터 변수에 저장한다. 이 경우는 배열 이름의 decay와 구분해야 한다.

```cpp
int* dynamicArray = new int[3]{1, 2, 3};

delete[] dynamicArray;
```

현대 C++에서는 직접 `new[]`와 `delete[]`를 관리하는 대신 `std::vector` 같은 컨테이너를 사용하는 경우가 많다.

<br>

## `std::vector`는 배열처럼 decay하지 않는다

`std::vector`는 내장 배열이 아니므로, 벡터 이름이 자동으로 첫 번째 원소의 포인터로 변환되지는 않는다. 원소를 가리키는 포인터가 필요하면 `data()`를 사용한다.

```cpp
#include <vector>

std::vector<int> numbers = {1, 2, 3};
int* ptr = numbers.data();
```

<br>

## 헷갈린 점과 해결

“포인터는 정적으로 할당된 배열에만 접근할 수 있다”는 설명은 정확하지 않다. 포인터는 저장 위치가 스택, 정적 저장 영역, 힙 중 어디인지와 상관없이, **타입이 맞고 유효한 객체나 원소의 주소**를 가리킬 수 있다.

array-to-pointer decay는 내장 배열 이름이 식에서 첫 번째 원소를 가리키는 포인터로 변환되는 규칙이다. 배열이 저장되는 메모리 위치를 뜻하는 말은 아니다.

<br>

## 오늘 배운 내용 정리

내장 배열 이름은 대부분의 식에서 배열의 첫 번째 원소를 가리키는 포인터로 변환된다. 이때 변환된 포인터에는 배열의 원소 개수 정보가 포함되지 않는다. 배열의 저장 위치와 decay 규칙은 별개이며, `std::vector`는 자동으로 decay하지 않고 `data()`로 원소 포인터를 얻는다.
