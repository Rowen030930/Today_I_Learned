# TIL: 프로세스와 스레드

<br>

## 오늘 배운 내용

프로그램은 디스크에 저장된 실행 파일이고, 프로세스는 그 프로그램이 실행되어 운영체제가 관리하는 상태다. 스레드는 프로세스 안에서 명령을 실행하는 작업 단위다.

프로세스와 스레드는 둘 다 프로그램 실행에 필요하지만, 메모리를 사용하는 방식이 다르다.

---

<br>

## 1. 프로세스(Process)

프로세스는 실행 중인 프로그램이다. 운영체제는 프로세스마다 독립된 가상 메모리 공간을 제공한다.

프로세스의 메모리 공간은 개념적으로 다음 영역으로 나눌 수 있다.

```text
Code   : 실행할 프로그램의 명령어
Data   : 전역 변수와 정적 변수
Heap   : 실행 중 동적으로 할당하는 메모리
Stack  : 함수 호출 정보와 지역 변수
```

일반적으로 한 프로세스의 메모리는 다른 프로세스에서 바로 접근할 수 없다. 프로세스끼리 데이터를 주고받으려면 파이프, 메시지, 소켓, 공유 메모리 같은 별도의 통신 방법을 사용한다.

---

<br>

## 2. 스레드(Thread)

스레드는 프로세스 안에서 실제 작업을 실행하는 단위다. 한 프로세스에는 스레드가 하나만 있을 수도 있고, 여러 개가 있을 수도 있다.

같은 프로세스에 속한 스레드들은 다음 자원을 공유한다.

- Code 영역
- Data 영역
- Heap 영역
- 프로세스가 가진 파일이나 핸들 같은 자원

각 스레드는 실행 흐름을 따로 유지해야 하므로 자신만의 Stack과 레지스터, 실행 위치를 가진다.

```text
프로세스
├── 공유: Code, Data, Heap
├── 스레드 A: Stack, 레지스터, 실행 위치
└── 스레드 B: Stack, 레지스터, 실행 위치
```

스레드마다 Stack이 따로 있으므로 한 스레드의 지역 변수는 다른 스레드의 지역 변수와 자동으로 공유되지 않는다. 반면 Heap의 데이터는 같은 프로세스의 여러 스레드가 함께 접근할 수 있다.

---

<br>

## 3. 프로세스와 스레드 비교

| 구분 | 프로세스 | 스레드 |
|---|---|---|
| 의미 | 실행 중인 프로그램 | 프로세스 안의 실행 단위 |
| 메모리 | 일반적으로 독립된 주소 공간을 사용 | 같은 프로세스의 Code, Data, Heap을 공유 |
| Stack | 프로세스 안의 각 스레드가 별도로 가짐 | 스레드마다 별도로 가짐 |
| 생성과 전환 | 대체로 더 많은 운영체제 자원이 필요함 | 대체로 프로세스보다 가벼움 |
| 데이터 전달 | 프로세스 간 통신 수단을 사용 | 공유 메모리를 통해 데이터를 주고받을 수 있음 |
| 주의점 | 다른 프로세스 메모리에 직접 접근하기 어려움 | 공유 데이터를 동시에 수정하지 않도록 주의해야 함 |

생성과 전환에 드는 비용은 운영체제와 상황에 따라 달라질 수 있다. 따라서 “프로세스는 항상 느리고 스레드는 항상 빠르다”라고 단정하기보다는, 스레드는 메모리와 자원을 공유하기 때문에 작업 간 데이터 전달이 편리한 대신 동기화가 필요하다고 이해하는 편이 정확하다.

---

<br>

## 4. 스레드가 공유 데이터를 다룰 때

여러 스레드가 같은 데이터를 동시에 읽는 것은 문제가 없을 수 있다. 하지만 여러 스레드가 동시에 같은 값을 변경하면 실행 순서에 따라 결과가 달라질 수 있다.

예를 들어 두 스레드가 같은 변수를 1씩 증가시키면, 의도한 결과는 2 증가지만 실제 결과는 1만 증가할 수도 있다. 두 작업이 값을 읽고 쓰는 과정이 서로 겹칠 수 있기 때문이다.

이처럼 공유 데이터에 대한 접근 순서 때문에 결과가 달라지는 문제를 **경쟁 상태(Race Condition)**라고 한다. 뮤텍스 같은 동기화 도구를 사용하면 한 번에 한 스레드만 특정 데이터에 접근하도록 제한할 수 있다.

<br>

## 5. 게임 클라이언트에서의 예

게임에서는 입력 처리, 게임 로직, 렌더링, 리소스 로딩처럼 서로 다른 작업이 필요하다. 작업을 여러 스레드에서 처리하면 일부 일을 동시에 진행할 수 있다.

예를 들어 게임의 메인 작업이 진행되는 동안 별도의 작업 스레드가 파일이나 데이터를 준비할 수 있다. 다만 여러 스레드가 같은 게임 데이터를 함께 수정한다면 데이터 접근 순서를 관리해야 한다.

```text
메인 작업: 입력 처리와 게임 상태 업데이트
보조 작업: 필요한 데이터 준비
렌더링 작업: 화면을 그리기 위한 작업
```

실제 엔진은 각 작업을 여러 방식으로 나누어 처리할 수 있다. 어떤 작업이 어느 스레드에서 실행되는지는 엔진의 구조와 기능에 따라 다르다.

## 헷갈린 점과 해결 과정

- **스레드는 프로세스와 별개의 프로그램인가?**  
  아니다. 스레드는 프로세스 안에서 실행되는 작업 단위다.

- **같은 프로세스의 스레드들은 모든 메모리를 공유하는가?**  
  아니다. Code, Data, Heap 등은 공유하지만 Stack은 스레드마다 따로 가진다. 각 스레드는 자신의 실행 위치와 레지스터도 따로 유지한다.

- **프로세스는 메모리를 절대 공유할 수 없는가?**  
  일반적으로 서로 독립된 주소 공간을 사용하지만, 공유 메모리 같은 운영체제 기능을 이용해 데이터를 공유할 수 있다. 다만 별도의 설정과 관리가 필요하다.

- **스레드를 많이 만들면 무조건 빨라지는가?**  
  아니다. 작업을 나누고 조정하는 데도 비용이 든다. 공유 데이터 동기화가 복잡해질 수도 있으므로 작업에 맞게 사용해야 한다.

## 오늘 배운 내용 정리

- 프로세스는 실행 중인 프로그램이며, 일반적으로 독립된 메모리 공간을 가진다.
- 스레드는 프로세스 안에서 명령을 실행하는 작업 단위다.
- 같은 프로세스의 스레드들은 Code, Data, Heap과 프로세스 자원을 공유한다.
- 각 스레드는 Stack, 레지스터, 실행 위치를 따로 가진다.
- 스레드가 공유 데이터를 동시에 수정하면 경쟁 상태가 발생할 수 있어 동기화가 필요하다.
