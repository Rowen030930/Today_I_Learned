## 프로젝트 폴더와 Git 관리

`.editorconfig`는 여러 편집기와 IDE에서 코드 작성 형식을 일관되게 맞추도록 돕는 설정 파일이다. 들여쓰기나 줄바꿈 같은 편집 규칙을 프로젝트 단위로 공유할 수 있어, 개발자마다 다른 편집기를 사용해도 코드 형식이 불필요하게 달라지는 일을 줄여준다.

프로젝트 폴더에서 `.editorconfig`가 루트에 있는 것을 확인했다. 이 파일의 실제 규칙은 파일을 열어 확인해야 하므로, 설정값은 확인한 뒤 별도로 기록한다.

Unreal 프로젝트 폴더에는 직접 작성한 코드와 에셋 외에도 빌드나 에디터 실행 과정에서 다시 만들어질 수 있는 폴더가 생긴다. 이런 생성 파일은 저장 공간을 차지하고 다른 개발 환경에서 달라질 수 있으므로, Git에 올릴 파일과 구분해야 한다.

`.gitignore`는 Git이 추적하지 않을 파일과 폴더를 지정하는 파일이다. 언리얼 프로젝트에서는 다시 생성할 수 있는 빌드 결과물, 임시 데이터, 로컬 에디터 설정 등을 제외하는 데 사용한다. 반대로 `Source`, `Content`, `Config`, 프로젝트 파일처럼 프로젝트를 구성하는 데 필요한 내용은 보존해야 한다.

`.gitattributes`는 Git이 파일 종류별로 어떻게 처리할지 정하는 파일이다. 텍스트와 바이너리 파일의 구분, 줄바꿈 처리, Git LFS를 이용한 대용량 파일 관리 등에 활용할 수 있다. 언리얼의 에셋 파일처럼 일반 텍스트와 다르게 다뤄야 하는 파일이 있다면 저장소의 처리 기준을 이 파일에 정리할 수 있다.

폴더를 살펴보면서 생성된 폴더와 프로젝트에 필요한 파일을 구분하는 방법을 확인했다.

## Visual Studio와 에디터 단축키

오늘 정리한 단축키는 다음과 같다.

- `F5`: 디버깅하며 실행
- `Ctrl + Shift + F5`: 실행 중인 디버깅을 중지하고 다시 시작
- `Ctrl + B`: 프로젝트 빌드
- `Alt + P`: 언리얼 에디터에서 플레이
- `Esc`: 에디터 플레이 종료

Visual Studio의 명령 사용자 지정 화면에서 메뉴와 단축키를 확인할 수 있다.

## 헷갈린 점과 해결 과정

Visual Studio 프로젝트 파일과 Unreal 프로젝트 파일의 역할이 헷갈렸다. `.uproject` 파일은 Unreal Engine에서 프로젝트를 여는 기준이 되고, `.sln` 파일은 Visual Studio에서 C++ 코드를 작업할 때 사용하는 솔루션 파일이다. 프로젝트 파일이 보이지 않거나 Visual Studio에서 프로젝트 구성이 달라졌을 때는 Unreal Engine 프로젝트 브라우저나 프로젝트 파일 생성 기능을 통해 솔루션 파일을 다시 만들 수 있다.

또한 프로젝트 폴더 안에 있는 모든 파일이 Git에 올라가야 하는 것은 아니다. 프로젝트에 꼭 필요한 소스 코드와 에셋은 보존하고, 다시 만들 수 있는 생성 파일은 `.gitignore`에서 관리한다. 파일 자체를 저장소에서 어떻게 처리할지는 `.gitattributes`에서 정한다.

## 오늘 배운 내용 정리

Visual Studio의 C++ 개발 구성을 확인하고 Unreal Engine C++ 프로젝트의 주요 폴더를 살펴봤다. `.gitignore`는 Git에서 제외할 파일을 정하고, `.gitattributes`는 파일 종류에 따른 Git 처리 방식을 정한다. 프로젝트를 Git에 올릴 때는 필요한 코드와 에셋을 보존하면서 다시 생성할 수 있는 파일을 구분해야 한다.
